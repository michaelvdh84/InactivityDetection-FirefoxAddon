# Updating locally force-installed kiosks

This extension is distributed as a signed local XPI, not as a public add-ons
store listing. Version 2.7.2 retains the extension ID
`michael.vanderhoudelinghen@i-city.brucity.be` so the update can preserve existing
extension settings and its Managed Storage association. The repository previously
declared 2.6.0; 2.7.2 is intentionally higher than the deployed 2.7.1 package.

## Prepare the signed release

1. Run the checks in [README.md](../README.md#validation), then perform the
   private-window tests on a pilot kiosk with the same Firefox version as the
   fleet. The new cookie cleanup does not resolve Mozilla's separate private
   localStorage limitation.
2. Package the runtime files with `manifest.json` at the archive root, using the
   existing signing workflow. Keep the extension ID unchanged and ensure the
   internal manifest version is `2.7.2`. The filename alone is not a version.
3. Obtain the signed, self-distributed XPI using the same add-on identity as the
   existing release. Signing does not require a public AMO listing. Repacking or
   editing an already signed XPI invalidates its signature.

No signed XPI is generated by changing this repository. Production signing and
deployment remain separate steps; do not deploy an unsigned development archive.

## Replace 2.7.1 through ExtensionSettings

Perform this deployment during a maintenance window, with no citizen session
active. There is one Firefox restart to load the new policy and extension;
subsequent session cleanups keep the kiosk window open.

1. Copy the **signed** new package to
   `C:\Program Files\EPN\FirefoxConfig\inactivitydetection_for_epn-2.7.2.xpi`.
   Keep the previous package available for controlled recovery.
2. In the existing `policies.json`, replace only this extension's entry under
   `policies.ExtensionSettings`, preserving all other policies:

   ```json
   "michael.vanderhoudelinghen@i-city.brucity.be": {
       "installation_mode": "force_installed",
       "install_url": "file:///C:/Program Files/EPN/FirefoxConfig/inactivitydetection_for_epn-2.7.2.xpi",
       "updates_disabled": true,
       "private_browsing": true
   }
   ```

   The supported key is **`updates_disabled`**, with an `s`, not
   `update_disabled`. It disables automatic add-on updates. An administrator's
   changed `install_url` triggers policy-driven installation at startup; this
   does not require enabling store updates or manually uninstalling the add-on.
   Use the new filename/URL rather than relying on detection of a replaced file
   at the previous path, which may depend on Firefox version and cached policy
   installation state.
3. Validate the full JSON, close Firefox completely, and restart it with the
   kiosk's usual `-kiosk -private-window` arguments. Do not delete the profile or
   the extension's storage. Do not temporarily set `installation_mode` to
   `blocked`, since that uninstalls the extension.
4. On the pilot, verify `about:policies` shows the new URL and no policy errors.
   Verify version **2.7.2**, the unchanged extension ID, and private-window access
   in `about:support` / `about:addons`. Managed Storage and saved settings must
   still be present.
5. Test logout, private cookies, preserved configuration, and the fail-closed
   behavior before rolling out the same signed package and policy to the fleet.

The `private_browsing` policy requires Firefox 136 or Firefox ESR 128.8 or later.
Pilot verification is required on the actual kiosk version. External identity
provider sign-out still depends on the portal's External logout configuration.
